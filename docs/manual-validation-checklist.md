# QQ频道发帖人工验证清单

这份清单用于本人账号和本人管理的测试频道。请不要把 Token、Cookie、二维码或完整错误响应粘贴到公共仓库、聊天记录或日志中。

## A. 账号和频道准备

- [ ] 已确认测试账号是本人账号。
- [ ] 已确认目标频道由本人管理，且测试版块允许本人发帖。
- [ ] 已记录频道名称和版块名称；内部 ID 只保存在本地，不写入公开报告。
- [ ] 已准备一张小尺寸 JPG/PNG 图片。
- [ ] 已准备一个短小、可公开发布的 MP4 测试视频。
- [ ] 测试内容不含个人隐私、商业机密、版权不明素材或敏感信息。

## B. 手动客户端验证

- [ ] 手动发布一条纯文本 Feed，并确认它出现在目标版块。
- [ ] 手动发布一条带图 Feed，并确认图片正常展示。
- [ ] 手动发布一条带视频 Feed，并确认视频正常展示或可播放。
- [ ] 记录客户端显示的限制、审核提示、权限提示和分享链接表现。
- [ ] 记录目标内容是 Feed 帖子还是普通频道消息。

## C. CLI 环境验证

CLI 文档要求先通过官方登录流程获取凭证。不要手工复制浏览器 Cookie 代替扫码流程，也不要把 Token 写进脚本、Git、截图或命令历史。

建议只在本机 PowerShell 中执行版本和帮助检查：

```powershell
tencent-channel-cli version
tencent-channel-cli schema feed.publish-feed
tencent-channel-cli feed publish-feed --help
```

验证项目：

- [ ] CLI 版本满足社区文档要求。
- [ ] `schema feed.publish-feed` 能返回当前参数定义。
- [ ] 登录状态正常，或已按官方扫码流程完成登录。
- [ ] 未把凭证写入仓库或日志。
- [ ] 先执行 dry-run/参数检查（如果当前 CLI 支持），再做真实发布。

## D. 最小真实发布顺序

每一步之间保留足够间隔，避免连续重复发布。参数请以当前 `schema` 输出为准，不要直接照抄旧文章中的字段。

1. 纯文本短贴。
2. 单张图片短贴。
3. 单个小视频短贴。
4. 如确实需要，再验证 Markdown 或长贴。

每次测试记录：

| 项目 | 记录内容 |
| --- | --- |
| 时间 | 本地时间 |
| 内容类型 | 文本 / 图片 / 视频 / Markdown / 长贴 |
| 目标 | 频道和版块名称 |
| CLI 退出结果 | 成功 / 失败 |
| 帖子结果 | 分享链接或本地脱敏标识 |
| 错误类别 | 无 / 鉴权 / 权限 / 限流 / 内容 / 超时 / 其他 |
| 账号状态 | 正常 / 出现安全提示 |

## E. 失败处理规则

- 鉴权失败：停止测试，重新走官方扫码授权；不要尝试猜测或拼接 Token。
- 权限失败：确认账号角色、目标版块权限和频道归属；不要通过轮换账号绕过权限。
- 限流：停止重复请求，等待平台允许的时间；不要通过并发或账号轮换规避限制。
- 内容拒绝：换成无版权风险、无敏感内容的最小测试文本，不要反复提交同一内容。
- 超时：先确认平台是否已经创建帖子，再决定是否重试，避免产生重复帖子。
- CLI 崩溃或输出格式变化：保存脱敏后的错误摘要和 CLI 版本，暂不逆向或修改二进制。

## F. TG 定时采集自动排期验证

先在假 CLI、临时数据库或本人管理的测试频道验证，不要用生产频道连续触发。可观察数据库中的 `PublishPolicies`、`PublishGuildBudgets`、`ScheduleExecutions` 和素材 `Status/PublishAt` 完成本地验证。

- [ ] 首次运行无论选择“导入当前首页最新 20 条”还是“先导入当前首页，之后仅采新消息”，都先处理当前首页最新 20 条，再记录首页最高消息号水位；后续只采集高于水位的新消息。
- [ ] 后续运行先按发布时间从新到旧截取首页最新 N 条，再应用水位、包含词和排除词筛选；筛选后不足 N 条也不会翻页回读更早消息补足。
- [ ] 包含词留空时不限制消息，填写多个词时标题或正文命中任一即保留；排除词命中任一即丢弃，同时命中包含词和排除词时排除优先。
- [ ] 最新 N 条之外的较早消息即使命中包含词，也不会被回读补采；水位会推进到实际扫描窗口中的最高消息号。
- [ ] 定时配置的“常用计划”提供每 10 分钟、每 15 分钟、每 30 分钟、每 60 分钟、每天凌晨 2 点、工作日早上 9 点、每周一早上 9 点和每月 1 日早上 9 点等预设，并显示 10/30/60 分钟轮询快捷按钮；选择预设后保存并重新打开，常用模板、Cron 表达式和下次运行时间保持一致，切换“自定义”后可输入并校验 5 段表达式。
- [ ] 单条消息失败不会中断同批次后续消息；部分媒体失败但正文或至少一条媒体成功时仍创建素材，并显示“部分成功”。
- [ ] 失败消息会阻止安全水位越过它；同一批次中失败消息之后的其他消息仍继续处理，避免后续运行遗漏失败内容。
- [ ] 部分成功的素材保留成功媒体，本次不自动排期，后续运行也不会自动补齐缺失媒体；只有全部媒体失败且没有标题正文时才不创建素材。
- [ ] TG 并发设置为 1 时，两个不同计划同时触发“立即采集”只执行一个计划，另一个显示“排队 #序号”；前一计划结束后，后一计划自动开始。
- [ ] 将设置中的“TG 定时采集并发”调整为 2 后，两个计划可以同时执行；该设置不影响发帖计划并发，非法值会安全回退为 1。
- [ ] TG 并发为 2 时，其中一个计划失败不会导致同批次其他计划失败；每个计划仍独立保存终态和历史记录。
- [ ] 同一计划在执行中或排队中再次触发“立即采集”时，不会产生第二个队列项，也不会重复下载或重复入库。
- [ ] 执行中的行只禁用该行的编辑、启停和删除操作；“立即采集”切换为“取消采集”，其他行和页面级控件仍可正常操作。
- [ ] 取消排队中的行后，该行恢复空闲且不会开始采集；采集历史中新增一条“已取消”记录。取消当前采集会保留已完成内容，并继续处理后续排队任务。
- [ ] “取消全部任务”会取消当前采集和所有排队项，行状态与顶部进度在完成后复位；离开页面再返回时，执行中和排队中的行状态仍能恢复。
- [ ] TG 采集只请求一次频道首页，不翻页；按发布时间从新到旧最多处理 20 条，重复消息链接只处理一次，历史记录中的安全水位与实际运行一致。
- [ ] 点击计划行的“历史”可打开采集历史窗口，按计划、状态和关键词筛选，最多显示最近 500 条，并展示统计、首页水位、自动排期和脱敏错误摘要；每个计划仅保留最近 500 条。
- [ ] 删除定时采集计划后，该计划的采集历史同步删除；其他计划和其他账号的历史不受影响。
- [ ] 切换账号后，采集历史只显示当前账号的记录；未登录时不显示其他账号的历史。
- [ ] 频道请求或网络等批次级失败按 5、15、30、60、60、60、60 分钟的间隔自动重试；累计第 8 次失败后显示“失败（自动重试已停止）”，清空重试时间并停止常规 Cron 派发，之后可手工采集恢复。
- [ ] 列表分别显示“最近尝试”和“最近成功”；失败或取消不会覆盖上次成功时间。
- [ ] “健康状态”覆盖已停用、执行中、排队、等待重试、成功、部分成功、失败、已取消和从未采集，错误提示已脱敏。
- [ ] 同一连续失败周期内，定时或重试任务失败只发送一次托盘通知；手工采集失败、部分成功和成功不发送，成功或部分成功后重置通知状态，关闭通知开关后不再提示。
- [ ] 一个采集批次结束后表格自动刷新一次并显示最新状态；多个并发任务几乎同时结束时只触发一次合并刷新。
- [ ] 保存定时配置和分发规则时，任一分发规则无效会整体回滚，不出现计划已更新但规则仍旧的半保存状态。
- [ ] 未配置版块策略时，采集成功素材不会自动进入发布队列，并显示"未排期"统计。
- [ ] 配置并启用策略后，匹配分发规则的素材生成 `SchedulingMode=Auto`、`Status=Pending` 的未来计划。
- [ ] 首条延迟、随机间隔和发布时间窗口符合策略；跨午夜窗口也能落到窗口内。
- [ ] 同版块达到每日上限或频道预算后，不再为新素材生成计划，已有任务不被取消。
- [ ] 多条素材同时排队时不会突破版块额度、频道预算、队列上限或同版块并发数。
- [ ] 手工计划在自动策略关闭后仍可执行，且优先于自动计划。
- [ ] 自动发布遇到限流后改为未来 `Pending`，不会连续请求；遇到超时后标记为"待核实"，不会自动重试。
- [ ] 停用或删除策略不会取消已生成的自动计划，但不会再领取新的自动计划。
- [ ] 顶部导航只显示一个“发布中心”；“计划队列”“自动规则”“发布记录”三个页签可按需切换并加载数据。
- [ ] 所有新增查询和写入都按 `AccountKey` 隔离，切换账号后看不到其他账号的策略、预算和队列数据。

- [ ] 手工 TG 采集和 TG 定时采集都能在“自动选择 / 系统代理 / 代理池节点 / 在线解析”之间切换，并显示当前通道。

- [ ] “自动选择”在失败时按“直连 → 系统代理 → 代理池节点 → 在线解析”顺序回退；显式选中某个通道后失败不再自动回退。
- [ ] 手工和定时 TG 采集都有“包含词”和“排除词”：包含词用于限定保留范围，排除词用于剔除消息，两者同时命中时排除优先；任一列表留空时只跳过对应筛选。

## I. Gitee 版本更新检查

- [ ] 开启“启动时自动检查更新”后启动程序，主界面仍可立即操作；检查在约 3 秒后开始，不弹出阻塞式对话框。
- [ ] 启动检查发现更高正式版时，只在侧栏“交流反馈”上方出现紧凑更新条；无更新、检查失败或该完整 Tag 已跳过时不显示更新条。
- [ ] 点击侧栏更新条能打开“版本更新”窗口，显示当前版本、最新版本、正式版类型、发布时间、更新包名称、大小、SHA-256 和更新说明。
- [ ] 手动检查更新时，设置页先显示“正在查询 Gitee 最新发布…”，随后显示结果和最近检查时间。
- [ ] 手动检查发现更新时始终打开详情窗口，即使该完整 Tag 已被跳过；已是最新或检查失败时只更新设置页状态，不弹出提示框。
- [ ] “稍后提醒”或直接关闭详情窗口后，侧栏更新条仍保留。
- [ ] “跳过此版本”后详情窗口关闭、侧栏更新条隐藏；重启程序且 Release Tag 未变化时不再自动提示。
- [ ] Gitee 出现更新的 Release Tag 后，即使旧 Tag 已跳过，新版本仍会重新提示。
- [ ] Release 列表只有预发布版本时显示“暂无正式发布版本”，不会提示预发布版。
- [ ] Release 页面链接带临时 Token、查询参数、片段、非默认端口或指向其他仓库时，不会被展示、保存或打开；程序回退到本仓库对应的具体 Tag 版本页。
- [ ] Release 同时包含 Windows 包、源码 ZIP/TAR 和校验文件时，只识别 `QqChannelDesk-{数字版本}-win-x64.zip` 及同名 `.sha256`。
- [ ] Windows 包缺失时仍可查看 Release，窗口显示“未识别到 Windows 更新包”。
- [ ] 校验文件存在并有效时显示 64 位 SHA-256；读取超时、HTTP 失败、内容过大或无法解析时显示“校验文件读取失败”，但更新检查本身仍成功。
- [ ] 发布方未提供校验文件时显示“发布方未提供校验值”，不因此判定更新检查失败。
- [ ] 窗口明确提示程序不会自动替换文件；用户需关闭程序后手动解压覆盖。数据库、日志、素材和本地工具不在更新包内。
- [ ] 使用 `scripts/Build-UpdateZip.ps1` 构建时，若同名 ZIP 或 `.sha256` 已存在，脚本在任何构建开始前停止。
- [ ] 打包完成后同时生成 `QqChannelDesk-{Version}-win-x64.zip` 和 `QqChannelDesk-{Version}-win-x64.zip.sha256`，校验文件内容为 `SHA256  文件名` 格式。

## J. 单实例与计划任务防重复

- [ ] 启动第一个程序后再次双击同一程序，第二个进程应自行退出，任务管理器或进程列表中只保留一个 `QqChannelDesk.exe`。
- [ ] 将主窗口隐藏到托盘或最小化后重复启动，已有主窗口会恢复到前台并获得焦点，不会出现第二个主界面。
- [ ] 开启发布计划和 10/30/60 分钟 TG 定时采集后重复启动，只存在一套调度状态和一条启动初始化链路，不产生重复排队、重复采集或重复发布。
- [ ] 关闭剩余主实例后再次启动，程序可以正常成为新的主实例，不需要删除锁文件或重启 Windows。

## K. 内容采集统一收件箱与来源管理

以下检查优先使用临时数据库、本地样本页面、本地 RSS/Atom 样本和假 AI 服务完成；不得连接真实 TG、真实模型或执行真实发布。如必须观察真实来源，先确认公开站点和授权范围，且只做只读采集。

### 界面与流程

- [ ] 主界面“内容采集”默认显示收件箱、来源管理、采集记录、代理池四个页签；TG快采和 TG定时入口从来源管理页按需展开。
- [ ] 收件箱顶部输入公开 HTTP/HTTPS 地址并回车或点击“提取网页”；解析成功时打开“采集结果”弹窗，失败时显示明确的失败提示。
- [ ] “采集结果”弹窗在 960px 最小窗口宽度和常规桌面宽度下无遮挡；长标题、长正文和提示文字可换行或滚动查看。
- [ ] 采集结果弹窗只有“再次解析”和“保留草稿”两个操作按钮；窗口可使用原生关闭按钮退出，关闭未保留内容前出现丢弃确认。
- [ ] 正文中带 `img`、懒加载图片、`srcset` 或视频来源的公开文章，在采集结果中显示媒体数量和文件名；相对地址会按最终页面地址解析，正文外的导航图片不会混入。
- [ ] 点击“再次解析”换用下一条采集规则；规则耗尽后尝试 AI 兜底，AI 不可用或失败时提示手动调整。
- [ ] 点击“保留草稿”后条目以“待处理”状态出现在草稿列表；列表显示编号、标题、来源、状态、时间、解析方式，并支持分页。
- [ ] 草稿行可编辑、入库和删除；编辑弹窗只允许修改标题和正文，不显示备注、标签，但保存旧草稿时不会清空其历史备注和标签；AI 兜底条目显示“解析方式：AI 兜底”。
- [ ] 编辑已有草稿时能看到其现有媒体文件名或远程媒体名称，再次解析后媒体列表随新正文一起刷新。
- [ ] 搜索框可按标题、正文或来源过滤草稿；输入重复公开 URL 提取时能打开已有草稿，不重复保存。

### 来源与采集记录

- [ ] 新建 RSS/Atom 来源时必须填写公网 HTTPS 地址、来源名称并确认授权；频率最小 30 分钟。
- [ ] 新建来源弹窗选择“Telegram 频道”后表单收起，点击“打开 TG 定时采集配置”会跳转到 TG 定时页签。
- [ ] 新建单页来源后，立即采集会生成采集批次，内容进入收件箱待处理状态；批次执行期间该行操作置灰，结束后恢复并刷新。
- [ ] 到达来源频率或 Cron 时间后，统一调度器自动执行采集并生成“定时”触发批次；登录账号后调度器自动恢复，切换账号和退出程序时停止。
- [ ] 来源管理顶部显示来源数、启用数、今日待审、异常和今日成功；“待审”列与收件箱来源筛选中的待审计数一致。
- [ ] 暂停来源后不再进入自动调度；启用后可手动恢复。
- [ ] 删除公开网页来源只执行软删除，不会删除 `CollectedItems`、素材或历史记录。
- [ ] TG 来源以只读视图显示；立即采集和启停委托原 TG 调度器，旧 TG 历史和水位保持不变。

### AI 配置与安全

- [ ] 设置页可以保存 AI 开关、公网 HTTPS 服务地址、模型名和每日调用上限。
- [ ] 内容采集收件箱地址栏右侧的“系统提示词”可打开编辑弹框，首次打开显示默认文章采集提示词；修改保存后生效，恢复默认后重新使用内置提示词。
- [ ] API Key 输入框留空时保存不会清除旧 Key；页面只显示“Key 已配置/未配置”，不回显明文。
- [ ] 启用 AI 时，localhost、127.0.0.1、私有网段、用户信息或非 HTTPS 地址会被拒绝。
- [ ] 保存后检查本地数据库：配置只有加密 Key 摘要形态，没有 API Key 明文。
- [ ] 规则解析成功时不调用 AI；规则失败且来源开启 AI 时才调用假 AI。
- [ ] AI 返回非法 JSON、超时、鉴权失败、额度不足或提示注入时，批次状态能区分并保留可解释提示，不会自动入素材库或发布。
- [ ] 全局每日限额和单来源限额生效；日志、异常、截图和测试输出不包含 API Key、Cookie、Token 或二维码内容。

### 数据迁移与账号隔离

- [ ] 使用旧数据库副本启动后，`CollectedItems` 仍可读取；`OriginalContent` 从旧正文回填一次，重启后不重复改写。
- [ ] 新增 `CollectionSources`、`CollectionRuns`、`AiUsageCalls` 表后，旧频道、素材、发布记录、TG 配置和发布策略仍可打开。
- [ ] 账号 A 创建的来源、批次和 AI 用量在账号 B 下不可见；账号 B 不能通过旧 ID 修改账号 A 的数据。
- [ ] 退出程序并重启后，来源启停、频率、收件箱状态和采集记录仍保持一致。
