# QQ 频道发布台

Windows 本地 WPF 工具。当前支持运行环境诊断、CLI 官方扫码授权，以及由用户确认后执行单条文本、图片或视频 Feed 验证。

## 当前能力

- 检查 Node.js 是否可运行。
- 首次启动发现 Node.js 或频道 CLI 缺失时，询问用户是否自动安装；Node.js 使用 Windows `winget` 安装 OpenJS Node.js LTS，CLI 使用 npm 全局安装。
- 自动安装失败后在运行环境中提供手动重试；Node.js 还可打开官方下载安装页作为备用方式。
- 运行环境独立检测 FFmpeg；缺失时可手动从本地 `tools` 目录部署。程序在该目录查找名称符合 `ffmpeg-版本号-描述.7z` 或 `.zip` 的压缩包，并按版本号选最高版本；由应用内置的 SharpCompress 解压。开发运行时压缩包来自源码项目目录 `src\QqChannelDesk\tools`，解压到 `src\QqChannelDesk\tools\ffmpeg\bin`；发布时压缩包会复制到 exe 旁的 `tools` 目录并解压到 `tools\ffmpeg\bin`。不联网、不修改系统 PATH；删除对应程序/项目目录即可一并删除部署文件。
- 在 NPM 全局目录和应用工作目录查找 `tencent-channel-cli`。
- 通过 Node.js 自带的 `npm-cli.js` 读取全局安装目录，兼容 Windows 下 `npm.cmd` 无法由普通子进程直接启动的情况。
- 检查 CLI 版本（最低要求 1.0.6）及 `login status`。
- Node.js 可用但 CLI 缺失或版本不达标时，可手动确认后通过 npm 全局安装/升级 CLI。
- 对诊断输出中的常见 Token/Cookie 字段做脱敏。
- 诊断记录默认展示环境检查、安装、发布等必要操作摘要；打开“调试模式”后额外查看脱敏后的 CLI JSON 响应和详细日志。
- 常规操作和调试日志写入当前程序目录下 `logs\yyyy-MM-dd.log`，按本地日期每日生成文件；调试开关保存在 `%LOCALAPPDATA%\QqChannelDesk\settings.json`。
- 通过 CLI 官方扫码流程登录；二维码仅在授权窗口内显示，授权凭证由 CLI 保存和管理。
- 扫码授权成功后，从 CLI 同步当前账号可访问的频道及每个频道的版块；完整读取成功后在 SQLite 事务中替换本地快照。
- 频道、版块和发布记录统一存放在程序目录下的 `channels.db`（与应用 exe 同目录）；SQLite 包含 `Guilds`、`Channels`、`PublishRecords` 三张表。同步状态单独保存在旁边的 `channels.sync.json`，不存 Token 或 Cookie。旧版三表数据库会在首次启动时迁移频道数据。
- 在发布验证进度卡片中打开文本、图片或视频 Feed 弹窗；弹窗从 SQLite 读取频道/版块，提供“刷新频道数据”操作。刷新失败保留旧数据，但会禁用发布，直至同步成功。
- 发布前展示目标、内容和媒体文件名并要求二次确认；标题留空时发布短贴，填写标题时由 CLI 按长贴发布。
- 识别常见权限、限流、鉴权和内容错误；发布超时不自动重试。
- 用户二次确认后先创建 SQLite 发布记录，再调用 CLI；记录目标、类型、标题、媒体文件名、状态、错误摘要和可用帖子链接/ID，不保存正文、凭证或媒体完整路径。超时与程序异常退出均标为“待核实”，不自动重试；侧栏“发布记录”可查看最近 500 条及详情。
- “内容采集”提供本地网页收件箱和独立发布草稿箱：用户逐条输入公开 HTTP/HTTPS 网页，程序仅提取 HTML 标题与正文，限制响应类型、大小、超时和重定向，并阻止本机/私有/链路本地目标；不读取 Cookie、不访问登录页、不绕过验证码或反爬，也不下载媒体。
- 采集内容需由用户审核后保存，可编辑标题、正文、备注和标签，按关键词/状态搜索，设为待处理、保留或忽略；重复规范化 URL 会提示打开已有素材，无 URL 的手动素材允许重复。解析失败时仍可手动补全保存，错误摘要会保留在素材记录中。
- 收件箱和草稿箱数据也保存在程序目录下全局 `channels.db`，新增 `CollectedItems`、`ContentDrafts` 两张表；标签以 JSON 文本保存。草稿保留来源 URL，但发布正文不会自动附加来源链接；发布前仍走原有人工确认和发布记录流程，发布成功后草稿保留并更新发布次数/时间。
- 保存、编辑或发布采集内容前，请自行确认具有相应的保存、编辑和转载授权；界面提醒不替代授权判断。
- “素材仓库”支持手动创建/编辑文本、图片或视频素材，保存目标频道和版块、本地媒体文件或公开媒体链接及可选发布时间；图片可选择多个本地文件，视频选择一个本地文件。删除为软删除。发布时本地媒体直接作为附件交给 CLI，公开媒体链接会先下载并验证，再复用原有 CLI 确认发布流程；成功后素材保留并标记已发布。
- 素材设置未来发布时间后会在 `ScheduleExecutions` 中创建待执行记录；“自动执行发布计划”首次启动默认开启，程序运行期间会按发布时间和素材 ID 顺序执行到期计划。默认并发数为 1，可调整为 2 或 3。
- “启动程序时自动运行发帖任务”单独控制应用启动后的逾期计划补发；关闭时逾期计划保留，用户可以在发布计划页查看、取消或点击“立即检查”。计划保存即视为用户授权，后台执行不会弹出二次确认框。
- 计划执行不自动重试。权限、限流、内容拒绝等失败会回到待发布；超时或应用退出时无法确认结果的任务标记为“待核实”，需要用户检查频道后再决定是否重新安排，避免重复发帖。
- 系统设置支持“电脑开机后自动启动程序”，默认关闭。该选项只在当前用户的 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 中登记当前程序路径，不注册 Windows Service，也不携带发布参数、Token 或 Cookie。
- 系统设置支持“最小化界面到系统托盘”或“退出程序”，默认退出程序。托盘模式只让已经打开的程序继续运行；程序未打开时不会执行发布任务。托盘中的“退出程序”会停止计划执行器并真正退出应用。
- 开机启动只负责打开可见的 WPF 主程序；“自动执行发布计划”默认开启，但是否在程序启动后补发逾期任务仍由“启动程序时自动运行发帖任务”控制，后者默认关闭。
- 素材表保存在程序目录 `channels.db` 的 `Materials` 表，本地媒体文件路径随素材记录保存在数据库中。公开媒体链接只允许 HTTP/HTTPS，并通过公网地址检查后下载到程序目录 `tools\media-cache`；不会携带 Cookie。因下载文件需要写入程序目录，安装位置应允许当前用户写入。

随程序使用的 Gyan.dev FFmpeg Essentials 便携构建采用 GPL 许可证；部署前会在界面提示。若对外分发程序或 FFmpeg 压缩包，需评估并遵守对应许可证义务。

账号授权仍通过 CLI 自带的官方流程完成。本应用不采集 Token 或 Cookie；二维码和授权链接仅用于当前授权会话，不写入应用日志或配置。
诊断区只显示当前程序启动后的日志，不加载此前运行留下的日志文件内容。未开启调试时显示重要的 Info/Warning/Error 摘要；开启后额外显示详细操作和脱敏后的 CLI JSON，但错误代码值在界面隐藏。所有可记录日志均追加写入当前程序目录下 `logs\yyyy-MM-dd.log`；CLI 响应中的 Token、Cookie 等敏感字段会脱敏。扫码授权响应（含二维码和授权链接）因包含会话凭证，不记录原始内容，只记录授权流程状态摘要。
CLI 安装按钮会在用户确认后执行 `npm install -g tencent-channel-cli`，最长等待 5 分钟；不会自动提权或触发账号登录。

频道数据同步失败时旧缓存不会被覆盖，但同步状态会标记为失败，发布入口保持禁用。可在发布弹窗中手动刷新；只有频道及全部版块均成功读取后，缓存快照才会整体更新并重新允许发布。

扫码登录会在本机建立 CLI 授权状态。点击“预览并发布一条”并在确认框选择“是”后，会在本人目标频道创建真实帖子，发布前请确认账号、频道和文案正确。仅用于本人账号和本人管理的频道；超时后请先检查频道，避免重复发帖。

## 开发环境

- Windows 10 或更新版本
- .NET 8 SDK / Windows Desktop Runtime
- Node.js
- 用户自行安装的 `tencent-channel-cli`

## 运行

```powershell
dotnet run --project .\src\QqChannelDesk\QqChannelDesk.csproj
```

运行自动化测试：

```powershell
dotnet test .\tests\QqChannelDesk.Tests\QqChannelDesk.Tests.csproj
```

## 阶段门槛

当前支持单条文本、图片或视频 Feed 验证，以及单程序内的计划执行。短贴正文最多 1000 字，带标题的长贴正文最多 10000 字；图片数量遵循 CLI 的短贴 18 张、长贴 50 张限制；视频弹窗每次选择一个文件。模板、批量功能、多账号和复杂失败重试仍未实现；请先在本人测试频道确认三类发布链路和计划执行行为。
